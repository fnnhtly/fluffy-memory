# 滚蛋吧！猪 · 垂直切片演示（HTML）

## 怎么玩

直接双击 `prototype/index.html`（不需要服务器；`levels.js`、`game.js` 是同目录的脚本文件）。

| 操作 | 作用 |
|---|---|
| 左键点/拖零件槽 | 选中零件；从零件槽拖到网格可以连续放 |
| 左键点格子 | 放下当前零件（必须贴着木框）；同一格连点 = 1→2→3 叠高 |
| **按住已放零件拖动** | 换格子（叠放数量跟着走）；**拖出网格松手 = 卸下，零件回到待使用** |
| 拖到已被占的格子 | 放不进去 → 弹回原处（这是移动失败，不是卸下；两者结果不同） |
| 右键点格子 / `R` | 旋转该格零件（推进器方向用） |
| `Z` / `C` | 撤销上一步（整张图纸回到上一步，放/拆/卸下/换向/清空都算一步）/ 清空 |
| 空格 / 蓝色对勾 | 发射 |
| 右下角按钮 / `1` `2` `3` | 交互键（打气筒按住蓄力、松开放出） |
| **点车身** | 行驶中点车上的**沙袋**扔一个、**气球**扎破一个（不占交互键） |
| `T` | 打开数值调参面板（重力/扭矩/耗能/冲量/抓地/滚阻/交互键上限） |
| `H` | 零件说明（每个结构干什么用的） |
| `L` / 左上角 `☰` | 选关 |
| 顶部 1-1 … 1-6 | 切关 |
| `Esc` | 行驶中暂停；暂停面板里空格继续、`R` 回建造 |

六关都通了之后，可以回来用不同零件刷 ★★★（这就是文档说的"一关三倍内容量"）。
打通全部六关时，1-6 的结算卡上会写「整章通关」，右下角按钮变成「章节总览」。

## 现在这一版的数值基线

| 参数 | 值 | 说明 |
|---|---|---|
| 重力 | 16 m/s² | 文档 §3.2 |
| 逻辑步长 | 60 Hz + 4 子步 | 渲染帧率不影响结果 |
| 马达加速度 | 6 m/s² | 受抓地上限约束（打滑时更小） |
| 马达自带电量 | 12 | 只装马达能跑约 3 秒，装电池 +100 |
| 轮子抓地 | 泥 0.75 / 冰：木轮 0.15、铁轮 0.8 | 1-4 的核心差别 |
| 滚动阻力 | 低速 0.14 / 高速 0.06 | 决定"能滑多远"；陡于 tanθ≈0.14 的坡才会自己起步 |
| 交互键上限 | 3 | 交互件即键位（气球/沙袋不算，它们是点车身） |
| 气球浮力 | 1 个 1.2 kg，升速上限 2.5 m/s | 净重为负才升；离地 0.3 m 内自动扎破 |
| 沙袋配重 | 1 个 0.8 kg | 为了"抬头之前先压住" |

面板里都可以改，改完直接发射就能看手感。

## 这些**不可移植**到千星 Lua（步骤 3 必须写清楚）

| 这里用的东西 | 千星里要换成 |
|---|---|
| `requestAnimationFrame` + `acc` 累加 | 客户端 `OnUpdate(dt)` + 同一个固定步累加器（`script:EnableUpdate(true)` 必开） |
| DOM 鼠标事件（mousedown/mousemove/mouseup） | 客户端控件 `CursorClick/CursorDown/CursorDrag/CursorUp`（`Cell_*` 光标检测区域、`Tray_*` 预设按钮） |
| `Canvas 2D` 画地形/车 | 图元控件 + `imageColor`/`sizeDelta`/`localRotation`（只能 6 种图元）；地形要按"列带合并"画 |
| `levels/*.json` 运行时读取 | 关卡表内嵌成 Lua 表（客户端脚本没有文件 IO），由同一份 JSON 生成 |
| 直接把像素坐标画在屏幕上 | 千星原点在左下、Y 向上：设计坐标要换算成 `anchoredPosition` |
| 失败回放的数组重放 | 同样可行，但要自己维护 3 秒环形缓冲（Lua 表） |
| 物理：连续高度场采样 | 同样可行（不需要真刚体引擎，方案 B 单刚体 + 射线轮） |
| `localStorage` 存档 | 自定义服务端变量 / 存档字段（`goals` 三个布尔标记，星数现算） |

## 本版与 v1.0 文档的差异（都是实现过程中被物理逼出来的）

1. **1-1 / 1-2 / 1-5 改成"坡路开局"**：文档写的 1-1 是"30 m 平地 + 木框木轮"，但没有马达的车在平地上永远不会动。坡路既让关卡成立，也正好呼应 1-5 的 ★★★「重力即动力」。
2. **地形高度场做了平滑**：不平滑的话"1 格抬 1 米"就是 45° 斜面，需要 11.3 m/s² 的加速度才能上，比马达的 6 还高——任何车都上不去。平滑后同样的地形约 18°。
3. **1-4 的 ★★★ 从「不撞墙」改成「不翻车（倾角 ≤ 45°）」**：高度场地形里没有"墙"，而冰面打滑翻车才是真实风险。
4. **1-4 改成结冰助跑 + 1:2 冰坡**：木轮在冰上最大加速度 2.3 m/s²，坡需要 7.1 → 必然滑回来；铁轮 10.6 → 能上。这才是"材质对抗"的真差别。
5. **1-5 的沟改成 1 m 深、木箱在沟底**：3 m 深沟在无马达时爬不出来；1 m 深时 ★ 路线能靠惯性冲过、★★ 路线能下沟取箱再爬出。
6. **马达自带 12 电量**：文档 §6.1 给 1-5 只给马达不给电池，若马达完全依赖电池，则"用马达"这条路永远不成立。
7. **已知弱点**：1-5 的 ★★（拿沟底木箱）和 ★★★（不用马达）在实际物理下**可以一次拿全**——文档要求二者必须冲突，这条在切片里偏软，留到 2-5《悬崖快递》（气球/伞）再体现。
8. **1-6 的解法是一条时间轴，不是纯摆件**：气球升速固定在 2.5 m/s、水平 1.8–2.2 m/s，斜率的倒数约 1.4:1 —— "飞多远"实际是"要升多高"。所以 1-6 的地形是按这条斜率倒推画的：先扔沙袋减重起飞，途中扎掉 1 个气球降低浮力才能不被吹过头。
9. **终点有一个高度门槛（2.2 m）**：不然气球会把车直接飘过终点而不算到达。2.2 m 是六关静止车高的最大值（1-6 = 2.18 m），再高就有关卡会误判。
10. **关卡数据里的 9 个字段被删了**（第 56 轮）：`physics`（整块 4 个子键）、`buildArea`、`grid.cell`、`grid.px`、`start.row`、`goal.row`、`materials[].surfaceRow`、`chapter`、`note`。它们全都**有人写、没人读** —— 而 `surfaceRow` 更糟：9 段材质声明里 6 段说的是假的（1-1 声明地表在第 8 行，实际是 5~8 行的缓坡）。现在 `mapRows` 是地形的唯一真相，`game.js` 的 `BUILD_COLS/BUILD_ROWS/CELL` 与 `index.html` 的 `PPM` 是尺寸的唯一真相，出口 `tools/build_levels_js.js` 会拒绝任何一份带这些字段的 JSON。
