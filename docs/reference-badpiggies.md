## 1. 它到底是什么游戏（一句话）

不是"闯关"，是**载具工程解谜**。每关给你一箱有限零件和一个 6×8 见方的搭建区，
你要造出一台能把猪运到终点的东西。物理是 Box2D，猪没有手脚，掉出载具只能顺坡滚。

关卡目标（来自萌娘百科「关卡目标」节，原话）：

> 不同于《愤怒的小鸟》中打高分得 3 星，在《捣蛋猪》中需要多次尝试并搭建不同的载具
> 去达到不同的关卡目标才能获得全 3 星。**在大多数关卡中，除了第一颗星以外，
> 其余两颗星星不可能一箭双雕。**

这条是我们和参考**最大的机制差距**，见第 3 节。

## 2. 三星的五种"第三星"

参考里第一颗星永远是「猪到终点」，第二颗是「星盒」，第三颗从下面这套里挑一个：

| 第三星 | 图标语言 | 判定 |
|---|---|---|
| 限时 | 秒表 + 时间 | 在限定时间内通关 |
| 禁用某零件 | 零件 + 禁止符号 | 全程不使用该零件 |
| **不散架 KRAK SNAP** | 砰啪 + 禁止符号 | 载具不散架，**且猪不能从载具里掉出来**；过了终点之后的损坏不影响 |
| 双目标 | 雀斑猪 + 国王猪 / 鸟蛋 / 南瓜 | 两个都必须到终点，不分先后 |
| 速通（疾驶猪） | A/B 两档时间 | <A 三星，A~B 两星，>B 一星 |

**KRAK SNAP 是最经典的那一颗**，也是这套系统的灵魂：它把"造得结实"变成一件值得追求的事，
而不是"撞坏了就重来"。

## 3. 三星是累计的，不是一次性的

百度百科「基本玩法」原话：

> 游戏中的每一关的三星是采用累计的方式获得。有些关卡也许需要一次获取三星的条件，
> 分别三次获取也算作三星通关，只要达到三星条件即可。

也就是说：**一局只追求一颗星是正常玩法**。这一局只用最便宜的木框冲终点（拿 ★），
下一局多装两个箱子（拿 ★★），再下一局一个零件都不碰去冲条件（拿 ★★★）。
达成过的星**永久点亮**，不会因为下次失败而熄灭。

我们现在的实现是「一次跑完，把这一局同时满足的条件加起来」。
后果是：**玩家一旦没在一局里同时满足，就必须重来一局把两件事都做对**，
这让"追求第三星"变成惩罚而不是目标。这是必须改的。

## 4. 零件表（参考的完整清单，用来判断我们缺什么）

### 结构
| 件 | 关键属性 |
|---|---|
| 木框 | 轻，容易散架。**中空，能塞东西** |
| 铁框 | 重，不容易散架 |
| 弹簧 | 减震，也能连接（著名的"弹簧飞刀"BUG 就出在这） |
| 绳子 | 只能连接，**不能传动力**（这是它和弹簧的关键区别） |
| 分离器 | 把四周连在一起的东西分开；红黄绿蓝四色，各用一次 |

### 轮子
木轮（轻，易散架）/ 铁轮（重，不易散架）/ 小铁轮（轻小，能做倾斜、能做炮弹）/
**驱动轮**（提供动力，只有摩擦地面才走）/ 吸盘轮（抓地极强，能上天花板）/

### 发动机可驱动的工具（← 这一栏是"飞行"的来源）
| 件 | 效果 |
|---|---|
| 小螺旋桨 | 拉力 + 轻微升力（朝下除外）。不稳定 |
| 大螺旋桨 | 动力 + 升力，**非常稳定**，占 3 格，一般做直升机 |
| 电风扇 | 较弱推力 |
| 黄伞 | 反复开合提供动力，不稳定；打开时当降落伞 |

### 发动机**不可**驱动的工具（手动）
| 件 | 效果 |
|---|---|
| **气阀** | 手动喷气提供推力 ← 就是我们的打气筒 |
| 黑伞 | 手动开合；造成阻力减速，一开一合也能提供动力；能当降落伞 |
| 拳套盒 | 打拳套顶墙/顶地获得推力，能当武器和分离器 |
| 吸盘枪 | 射吸盘吸墙，能攀爬。**全作唯一放置阶段有 8 个可选方向的道具** |

### 动力源
- 永久：雀斑猪（一点点）/ 绿电机（少）/ 棕柴油（中）/ 红涡轮（多）/ 核（先缓后快）
- 一次性：雪碧 = 可乐 < 红火箭 = 蓝火箭；TNT
- **只要中间有"动力连接件"（框/可乐/火箭/分离器/弹簧都算，绳子不算），动力可以叠加**
- 太多动力源反而更慢（重量压过推力）

### 飞行道具（← 我们完全没有）
| 件 | 效果 |
|---|---|
| 气球 | 提供升力。**一格可分别放 1/2/3 个**（三种独立道具）。碰到墙/地自动破，也可手动爆破 |
| 沙袋（重物） | 增重。一格可放 1/2/3 个。**行驶中可以手动卸载** |
| 木机翼 / 铁机翼 | 移动时产生升力，配合尾翼可平稳飞行；占 3 格 |
| 木尾翼 / 铁尾翼 | 随时产生升力/下压力，用来平衡 |

**气球 + 沙袋**是参考里最漂亮的一对：气球给浮力、沙袋给配重，
玩家靠"什么时候抛沙袋、什么时候扎气球"来控制高度。这不需要精细操作，
但需要预判——正是我们这套"预判型"手感的强项。

## 5. 其他值得抄的系统

- **疾驶猪**：A/B 双时间档，纯竞速，8 关。
- **沙盒**：11 个，纯创造，收集 20 个星盒即可过关。
- **猪王**：3 格宽 2 格高，很重，载着它容易散架，带着一起到终点 +1 星。
- **小鸟**：夜间关里有，太吵就醒，朝猪的位置发射（打不准，因为车在动）。
  红鸟/蓝鸟（分裂3只）/黄鸟（快而不准，能撞坏铁车）。
- **强化道具**：涡轮加速器、超级磁铁、超能胶（不散架）、夜视、超级机械工。

## 6. 我们和参考的差距，按"该不该补"排序

| # | 差距 | 影响 | 判断 |
|---|---|---|---|
| 1 | 三星不累计，一局定生死 | **玩家会被迫重刷，第三星变成惩罚** | **必须补**，改动集中在一处 |
| 2 | 没有 KRAK SNAP（不散架）第三星 | 木框耐久 3 段做了，却没人有理由去追求 | **必须补**，数据已经有了 |
| 3 | 没有气球 / 沙袋 | 游戏**只有水平方向**，没有"抬头" | **该补**，玩法增量最大、实现成本可控 |
| 4 | 没有一次性推力（火箭） | 缺少"什么时候点火"的节奏点 | 该补，和气球同批做 |
| 5 | 只有木框，没有铁框 | 没有"结实 vs 轻"的取舍 | 该补，成本很低 |
| 6 | 没有机翼/尾翼/螺旋桨 | 真飞行做不了 | **不补**。三维气动在 2D 顶视/横版里不成立，会变成假物理 |
| 7 | 没有弹簧/绳子/分离器 | 少了很多"机关"玩法 | 不补。切片范围 1-1~1-5，先把核心做扎实 |
| 8 | 没有猪王 / 小鸟 / 沙盒 / 疾驶猪 | 内容量差距 | 不补。这是后续章节的事，不是垂直切片的事 |

## 7. 结论：这一轮改什么

**只做第 1、2 条**（累计三星 + KRAK SNAP），因为它们是"系统级正确性"，
而且能在现有数据上直接落地，不引入新物理。

第 3、4、5 条（气球/沙袋/火箭/铁框）排下一轮，因为它们要动 `PARTS`、
物理步进、`drawPartShape`、预算表和关卡设计——体积是这一轮的三倍。

第 6 条起明确不做，理由写在这里，免得以后又被当成"忘了做"。

## 8. 第 1、2 条的落地记录（第 36 轮）

改完了，记下实际做了什么、以及落地后暴露的新问题。

| 项 | 落地方式 | 验证它的测试 |
|---|---|---|
| 累计三星 | 存档写 `goals = {arrive, boxes, challenge}`，星数由 `starsOf(goals)` 现算；金币也从 goals 推导，不再单存 `coins` | `test_coins.js`（18 断言，含旧存档迁移、分两次拿星） |
| KRAK SNAP | `damageCar` 记 `hullBroken` / `pigEjected`；`challengePass('noBreak')` 要求两条都不成立 | `test_no_break.js`（14 断言，含"只判木框会漏掉猪被弹出"） |

**顺带修的两处**：

1. `damageCar` 的 `vn > 14 ? 2 : 1` 是死代码 —— `maxSpeed = 12` 让 30 米落体
   也只能到 11.97 m/s。改成 `≥11 散架 / 8~11 扣 2 / 6~8 扣 1`，三段都实测可达。
2. 1-2 名为「按一下」却奖励"不按"（`pumpPress max 0`，而不按也能通关）。
   把终点从 col 12 挪到 col 14 —— 不装打气筒最远滑到 x=13.26，
   于是"必须按"是结构性的，且按下时机窗口有 1.7 秒宽。第三星改成 `max 1`。

**落地后暴露的新问题**（写在这里，别当成没发生）：

- 「不散架」这颗星在现有五关里几乎不会失败。400 种随机造法里只有 1% 撞碎木框，
  五关标准解全部毫发无损。**它是可达的，但还不够"值得追求"** —— 需要一个
  专门为它设计的长下坡 + 落地关，那要等气球/沙袋上线、关卡重新排布之后。
- 金币仍然没有消费出口。参考里金币也不直接买东西（它是星级/收集的副产物），
  所以这条不算缺陷，但需要后续章节的商店才能闭环。

## 9. 第 3 条的落地记录（第 37 轮：气球 + 沙袋）

按 §6 第 3 条做。做完之后游戏从"只有水平方向"变成"能抬头"，
代价是全部四层都要动：`PARTS`、物理步进、渲染、关卡。

### 9.1 和参考的三处**故意不同**

| 项 | 参考 | 我们 | 为什么 |
|---|---|---|---|
| 一格的容量 | 1/2/3 个是**三件独立零件** | **一件零件 + 同格堆叠**（点同一格 1→2→3→1） | 托盘已 9 格，再拆 6 格会撑破 1280 宽；交互上"点同一格"和"选 2 个装"是同一件事 |
| 上升速度 | 靠浮力/重力/阻力自然收敛 | **定速封顶 2.5 m/s** | 见 §9.3，阻尼收敛对净浮力极度敏感，玩家学不到规则 |
| 触发方式 | 手动爆破 / 卸载 | **点车身**（`tapAt`，半径 0.85 m） | 面板只有 3 个交互键位，要留给打气筒这类真驱动器；点气球是最直觉的操作 |

### 9.2 落地面

| 项 | 落地方式 | 验证它的测试 |
|---|---|---|
| 气球 | `liftMass 1.2`，`fy += G·liftMass`，`vy` 钳到 2.5 | `test_parts_lift.js`（34 断言） |
| 沙袋 | `mass 0.8`，扔一个少 0.8 kg，掉出去的是视觉自由体 | 同上 |
| 堆叠 | `cellCount` / `maxStack 3` / 预算按个数扣 / 第 4 次回绕到 1 | 同上 |
| 不占交互键 | `tapOnBody: true` → 跳过 `interactCap` | 同上（9 个气球也不会超上限） |
| 碰地自动破 | 球心低于地表 0.3 m → 破一个，一帧最多一个 | 同上 |
| 关卡 | `levels/06.json` + `SPECS['1-6']` | `test_1_6.js`（18 断言） |

### 9.3 两条实测结论（都已写进 gdd §5.3 / §5.4）

1. **阻尼收敛不可用**。终端速度 `v = G·(lift−m)/(k·lift)`，挂 6 个气球只有 0.46 m/s。
   改定速封顶后能带起来就恒以 2.5 m/s 上升，与挂几个无关 —— 玩家一次就能试出"够不够"。
2. **只判 x 的终点会让气球流当场塌掉**。车一直上飘、`vx` 还有 2 m/s，
   "挂一堆气球什么都不做"也能飘过终点线（实测 `maxY=19.9` 判 win）。
   中间那版"离地 ≤3 m"更隐蔽：车飞过旗子之后才落下来，落地时 x 早已越线，照样判赢。
   最终口径 `越过终点线 && |y−surfaceY(x)| ≤ 2.2 m`。

### 9.4 落地后暴露的新问题

- **气球把"斜坡"变成了新变量**。浮力直接加在 `fy` 上，而轮子法向力由穿透深度算出，
  两者互不知情 → 浮力到 80% 车重时摩擦上限同步下降，带气球的车在斜坡上滚得更慢。
  这不是 bug（"漂浮的车抓地差"是对的），但它让 `creepBrake` 的旧实现变成了 bug：
  刹车对 1.5 m/s 以下无条件生效，而带球车沿坡每帧只涨 0.011 m/s、刹车每帧抹 4% ——
  车永远到不了 1.5，10 秒只挪 2 米。修法是斜坡上（`|slope|>0.12`）放行。
  **教训：任何"全局减速"都必须先问「它在斜坡上合理吗」。**
- **气球流让"撞天花板"成为常见死法**（参考里没有这个问题，因为它的关卡有房顶）。
  补了 `flew_away`，并给了专属文案「飘得太高，飞出地图了」。
- **关卡形状被物理锁死**。上升定速 2.5、水平 1.8，轨迹斜率锁在约 1.4:1 ——
  前进 1 米就要升高 1.4 米。于是"横向跨远沟"这类关卡在几何上不成立
  （8 格沟要升 10 米，车飘出画面，可过窗口 0.1 s）。
  只能改成"纵向要够高"：一格沟 + 3.3 米立面墙，窗口从 0.1 s 变成 ±0.8 s。
  **这是本作第一条"关卡想象力被物理参数限制"的记录**，以后再设计飞行关要先算这条斜率。
