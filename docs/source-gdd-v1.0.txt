# 第一章　项目概述
## 1.1　一句话概念
一款“建造—发射—围观”的 2D 物理造车解谜游戏。玩家用有限的零件拼出一辆注定会散架的载具，把猪送到终点。核心乐趣不在操作精度，而在设计是否成立。
## 1.2　目标用户与平台
- 主力人群：12–35 岁，玩过《愤怒的小鸟》《人类一败涂地》《桥梁工程师》，喜欢“看物理出错”的观赏性。
- 次级人群：沙盒建造爱好者（UGC 关卡的供给方），以及短视频平台的“翻车集锦”观众。
- 平台策略：移动端竖屏为主，单指可玩；PC 端提供键鼠 + 关卡编辑器，作为 UGC 生产基地。
## 1.3　设计支柱与反支柱
四条支柱决定了我们做什么；四条反支柱决定了我们拒绝什么。任何新功能必须至少强化一条支柱，且不得触碰任何一条反支柱。
[表格]
| 支柱 | 含义 | 反面（我们不做的事） |
| 建造即解谜 | 关卡的核心难度在于“怎么搭”，而非“怎么操作” | 不做需要精准操作的高难度动作关卡 |
| 失控的观赏性 | 载具必须是“活的”：晃、散、翻、炸，失败要好看 | 不做硬编码轨迹的伪物理 |
| 失败成本趋近于零 | 重开 ≤ 1 秒，失败信息必须可读 | 不做长流程、不做读条、不做惩罚 |
| 零件即语言 | 零件数量克制，靠“组合”而非“数量”产生深度 | 不做几十种花哨零件的收集式堆砌 |
[/表格]
不做战斗、不做联网对抗、不做数值养成。养成只服务“解锁零件”，且必须保证每一关在任何解锁状态下都可通。
# 第二章　核心循环
## 2.1　三层循环
[表格]
| 层级 | 时长 | 循环内容 | 玩家的心理状态 |
| 微观 | 30 秒 – 3 分钟 | 看地形 → 选零件 → 搭车 → 发射 → 观察物理 → 失败 / 成功 → 一秒重开 | “这次一定行” |
| 中观 | 10 – 20 分钟 | 连续 3–5 关 → 得到零件箱 → 新零件解锁 → 回老关卡用新零件刷三星 | “原来还能这么玩” |
| 宏观 | 数天 | 章节推进 → 沙盒自由造 → UGC 关卡 → 周挑战 | “我是工程师” |
[/表格]
## 2.2　核心张力
核心张力 = 建造期的“确定性” × 运行期的“不可控性”。
所有机制设计都必须强化这个对立：建造时玩家是全知全能的工程师，可以精确到每一格；发射后玩家只能旁观，最多按三个键。这个落差就是本作的全部戏剧性来源。
### 由此推导出的三条铁律
- 铁律一：建造界面必须给出足够的信息（重心、总重、总推力、预计最高速度），让玩家的失败可以归因。
- 铁律二：发射后不得提供任何“修正建造”的手段。不能在空中加零件、不能重摆重心。
- 铁律三：失败必须比成功更好看。翻车、爆胎、猪被弹飞，都要有专门的演出与音效。
# 第三章　核心机制
## 3.1　建造系统
### 基础规则
- 网格化：1 格 = 1 米 = 32 逻辑像素。建造区通常 6×8 格，随关卡变化。
- 朝向与挂载点：每个零件有确定的挂载面。木框 / 铁框是唯二的“结构件”，其余零件必须挂在结构件的挂载点上。
- 刚体连接：默认所有连接视为刚性；解锁“铰链”后才出现柔性节点。连接点有耐久值，超过阈值断裂。
- 质量与重心：每个零件有独立质量，建造界面实时显示重心图标。倾覆判定用重心投影是否落在支撑多边形内。
### 约束设计
- 限制库存，不限制摆放。零件种类与数量由关卡给定，通常比标准解多 1–2 个，形成“有冗余但不富裕”的紧张感。
- 不做撤销栈，做“一键清空 + 撤销上一件”。撤销栈在触屏上是操作地狱，且会鼓励玩家无脑试错。
- 零件箱取用即锁定。发射后不可更换、不可补充，补给点只出现在长关卡的中段。
### 新手友好机制
- 有效挂载点高亮。拖拽零件时只高亮可吸附的位置，靠近自动吸附，不需要像素级对齐。
- 预设模板。提供“小车 / 弹射器 / 气球吊篮”三套模板，仅在前 10 关可用，第 11 关后隐藏。这是防卡关的保险丝。
- 实时仪表。建造界面下方常驻四个数值：总重、总推力、重心偏移、预计爬坡角。
## 3.2　物理与驱动
### 物理参数（首版调参范围，非最终值）
[表格]
| 参数 | 取值 | 调参意图 |
| 重力加速度 | 16 m/s²（而非 9.8） | 卡通化，下落快，节奏干脆 |
| 模拟步长 | 60 Hz 固定步长 + 4 子步 | 保证低端机与高配机的模拟结果一致 |
| 摩擦系数 | 木 0.6 / 铁 0.45 / 冰 0.05 / 粘液 0.9 | 地形材质即难度 |
| 空气阻力 | 线性项 0.02 + 平方项 0.0008 | 让“伞”和“螺旋桨”有意义 |
| 碰撞检测 | 连续检测（CCD）+ 空间哈希 | 高速弹射不能穿模 |
| 最大刚体数 | 单场景 64 个 | 保证移动端帧率下限 30 fps |
[/表格]
### 三类动力源
动力件必须分三类，这是本作操作深度的来源，也是关卡设计的三把不同钥匙。
[表格]
| 类型 | 工作方式 | 代表零件 | 设计作用 |
| 被动持续型 | 放上去就工作，消耗能量条 | 气球、螺旋桨、马达 | 给玩家“稳定但昂贵”的确定性 |
| 一次性脉冲型 | 建造时决定朝向，运行中按一次即耗尽 | 可乐瓶、TNT、弹簧板 | 制造“关键一脚”，用完就没有 |
| 手动交互型 | 运行期需要玩家持续或择机输入 | 打气筒、雨伞、沙袋、磁铁 | 把“建造决策”转化为“操作手牌” |
[/表格]
## 3.3　交互件即键位（本作的核心差异化）
建造时每放置一个“手动交互型”零件，运行时屏幕上就自动多出一个按钮，上限 3 个；达到 3 个后不再允许放置该类零件。于是“造什么”直接定义了“运行时你能按什么”。
玩家在造车阶段就要规划自己的操作手牌。例如造了“打气筒 + TNT + 伞”，运行时就只有三个键：泵、引爆、开伞。这三个键的按下顺序，往往就是这一关的解法。
### 这条规则解决了一个旧问题
传统造车游戏的操作是“没有操作”——发射后纯看戏，玩家在运行期是闲置的，容易走神。而如果给太多实时操作，又会退化成动作游戏，破坏“建造即解谜”的支柱。“交互件即键位”把操作量交给玩家自己决定：想要更多操作，就要付出更多零件与重量。这是一次有代价的选择，而不是一次免费的增强。
## 3.4　运行期控制与镜头
- 唯一实时输入：交互键（≤ 3 个）+ 一个“刹车 / 松手”键（松开所有轮子，让车自由滚动）。
- 发射前 3 秒俯视全景：倒计时期间镜头拉远到能看见全部地形，强制玩家“记住地图”。发射后你会看不清。
- 运行期镜头：自动跟随载具，允许双指缩放拉远，允许小幅左右拖动但不能离开载具视野。
- 不做回放倒带：死亡后只提供 3 秒慢动作回放，不提供倒带重来——重来要重新面对同一段地形，才有学习感。
## 3.5　胜负判定与三星
[表格]
| 目标 | 内容 | 设计目的 |
| 主目标 | 猪抵达终点旗 | 保证通关 |
| ★ | 通关 | 保底，几乎所有玩家都能拿到 |
| ★★ | 收集关卡内全部“木箱”（通常 1–3 个，藏在岔路、高空、机关背后） | 强制绕路，考验路线设计 |
| ★★★ | 关卡专属挑战（限时 / 零件数 ≤ N / 零受损 / 一次通过） | 难度上限的载体，服务硬核玩家 |
[/表格]
### ★★★ 必须与 ★★ 冲突
这是全部关卡设计的核心原则：拿木箱的路线往往更绕、更耗零件；限时挑战要求抛弃安全冗余；零件数限制逼玩家做减法。同一个关卡，玩家要玩三遍、造三种车——这就是“一个关卡三倍内容量”的做法。
反例：如果 ★★ 和 ★★★ 可以一次拿全，玩家就只会玩一遍，关卡的价值直接砍掉三分之二。
## 3.6　失败与重试
- 死亡判定：猪受到 > 2 点伤害 / 掉出下边界 / 卡死 5 秒无位移。
- 失败回放：死亡瞬间 0.4 倍速回放 3 秒，用箭头标注“翻车原因”（重心偏移 / 动力不足 / 结构断裂）。
- 一键重开：保留上次建造的载具，直接回到建造界面并默认载入上次方案。玩家只改一个零件再试。这是留存命脉。
- 智能提示：同一关失败 3 次后弹出“建造建议”，只给方向不给解法。
✔ 正确提示：“也许需要更大的轮子。”　　✘ 错误提示：“在第二格放气球。”

## 4.4　零件设计纪律
- 一件零件只解决一个问题。如果一个零件既能当动力又能当护甲，它就会吃掉整个设计空间。
- 克制数值，放大组合。18 个零件两两组合有 153 种，这就够了。加到 40 个零件只会让玩家迷茫。
- 每个零件必须有“反制件”。气球 ↔ 尖刺，铁框 ↔ 重量，TNT ↔ 结构强度。反制关系是关卡设计的弹簧。
- 不允许“纯陷阱”零件。任何零件在至少一种语境下必须是好选择。玩家被坑一次可以，被坑两次就不玩了。
# 第五章　关卡设计方法论
## 5.1　关卡语法：一切关卡都是“门”的组合
一个关卡 = 起点 + N 个门（Gate）+ 终点 + 木箱 + 零件箱。关卡策划的工作是“组合门”，而不是“发明关卡”。
[表格]
| 门的类型 | 表现 | 玩家要解决的问题 |
| 地形门 | 沟壑、上坡、天花板、窄缝、斜坡 | 能不能过 / 车够不够矮、够不够高、够不够长 |
| 物理门 | 冰面、粘液、风区、水流、磁区 | 运动方程被改写，原有的车可能直接失效 |
| 资源门 | 路上的零件 / 能量 / 木箱 | 强制绕路，制造路径选择 |
| 时间门 | 崩塌地形、移动平台、周期机关 | 强制提速，压缩建造冗余 |
| 结构门 | 尖刺、落石、爆炸、火焰 | 强制“车不能被撞到”，考验耐久与走位 |
[/表格]
设计流程：先定“这一关要考哪个门”，再搭地形，最后才决定给什么零件。
绝不允许“先想一个好玩的零件，再硬造一个关卡”——那是内容消耗型设计，做不长。
## 5.2　难度曲线（首发 4 章 × 20 关 = 80 关）
[表格]
| 章节 | 关卡段 | 教学重点 | 难度感 | 目标失败次数 |
| 第一章　泥巴地 | 1-1 ~ 1-20 | 建造、轮子、马达、地形门 | 全程可通，建立信心 | 0–2 次 |
| 第二章　风车坡 | 2-1 ~ 2-20 | 弹射、气球、空气、资源门 | 开始需要试错 | 2–3 次 |
| 第三章　铁锈厂 | 3-1 ~ 3-20 | 铰链、绳索、TNT、结构门 | 需要“想”而不是“试” | 4–6 次 |
| 第四章　天空岛 | 4-1 ~ 4-20 | 磁铁、多段载具、时间门 | 三星需要精通 | 6–10 次 |
[/表格]
### 必须遵守的节奏规则
- 每 4 关插入 1 个“简单关”（送分），让玩家从挫败里爬出来。
- 每 5 关必有 1 个“新零件关”，且该关只有一种解法能过——强制玩家学会它。
- 每章最后 2 关是本作最高难度，允许失败 8 次以上。
- 任何关卡的建造 + 运行总时长不得超过 2 分钟。超过就拆成两关。

## 5.5　关卡制作规范（Checklist）
每张关卡在提交前必须全部打勾：
- ①必须有至少一条“笨办法”通关路径，保证任何玩家都能过。
- ②★★★ 必须只有一条解，且这条解必须是“玩家想出来的”而非“猜出来的”。
- ③每次给新零件，同一关必须包含一个“不用它也能过”的对照。
- ④禁止关卡长度超过 2 分钟（含建造）。超过就拆成两关。
- ⑤每个关卡的可视区域内不超过 3 种材质，视觉信息量必须低。
- ⑥关卡编辑器必须能一键“自动验证可通关”：用暴力搜索 AI 跑 5000 次随机建造，若 0 次通关则关卡报警。
## 5.6　沙盒与 UGC
- 沙盒地图：每章通关解锁一张，无目标、无限零件、可自由飞行，作为“解压区”与“灵感区”。
- 关卡编辑器：拖地形块 + 摆零件箱 + 设三星条件，产出分享码（字符串，可离线传播，不依赖服务器）。
- 每周挑战：官方给一张固定地图 + 固定零件，全球比拼“谁用的零件最少 / 谁最快”。
- UGC 关卡默认不显示星级，只显示“通关率”。避免玩家被劣质 UGC 的三星劝退。

# 第七章　经济与养成
- 不卖数值，不卖零件。全部零件靠推关解锁，氪金不能降低难度。
- 货币只有一种：齿轮。来源：首通（10）、三星（30）、每日挑战（50）。
- 消耗：外观（车漆、猪的帽子）、失败提示、沙盒扩建、关卡编辑器槽位。

# 第十章　实现与落地
## 10.1　物理方案三选一
[表格]
| 方案 | 做法 | 优点 | 代价 | 结论 |
| A　真物理 | 自研 2D 刚体 + 关节约束 | 还原度最高 | 碰撞稳定性、关节抖动、确定性回放吃掉 60% 工期 | 不推荐首版 |
| B　伪物理 | 网格连通块为单一刚体，轮子用射线贴地，散架播预设动画 | 100% 可控，零穿模，好调 | 牺牲“散架”的真实感 | 推荐首版 |
| C　混合 | 车为单刚体，TNT/强碰撞时断开连接生成新刚体 | 复杂度居中，保留关键戏剧性 | 需要维护刚体分裂的一致性 | 推荐正式版 |
[/表格]
## 10.2　数据驱动关卡
关卡不写死在代码里，而是“格子数组 + 实体配置表”。一张关卡 = 一个 JSON（见附录 B）。这样 80 关可以由关卡策划独立产出，程序只维护一个 300 行的加载器。
## 10.3　千星沙箱适配建议
- 优先做方案 B。2D + Lua 环境下自研完整刚体代价极高，而本作的乐趣 80% 来自“设计与结果”，不来自“真实的碎块”。
- 先不做关卡编辑器。手工关卡 + JSON 配置的成本只有编辑器的 1/5，且质量更可控。
- 交互件即键位非常适合触屏 UI。最多 3 个按钮常驻屏幕右下角，用客户端控件即可实现，不需要额外输入系统。
- 物理步进必须与渲染解耦。固定 60 Hz 逻辑步 + 插值渲染，否则慢设备上“看火”的节奏会完全乱掉。
## 10.4　版本节奏建议
本作的开发风险集中在“物理手感”和“关卡产能”两件事上，因此排期必须把这两件事的验证点前置。
[表格]
| 阶段 | 周期 | 交付物 | 验收标准（不达标就不进入下一阶段） |
| 原型期 | 4 周 | 可玩的单关：建造 + 发射 + 物理 + 一秒重开 | 10 名内部同事能连续玩 15 分钟不主动退出 |
| 垂直切片 | 6 周 | 第一章前 8 关 + 完整 UI + 占位音效 | 陌生玩家首关通关率 ≥ 80%，平均失败 ≤ 2 次 |
| 量产期 | 14 周 | 80 关 + 4 张沙盒 + 关卡编辑器 | 每关通过自动验证 AI，且人工试玩 ≥ 5 人签字 |
| 打磨期 | 6 周 | 性能、低端机适配、失败提示文案、UGC 审核流 | 红米 Note 10 上稳定 30 fps，包体 < 200 MB |
[/表格]
如果只能保一个里程碑，保“垂直切片”——它同时验证了物理手感和关卡产能，这两个数字一旦成立，剩下 80 关只是执行问题。

## C.5　一个必须注意的坑
喷火器的计时与物理步进必须共用同一个固定时间步。若火焰用渲染帧计时、物理用固定步，在 30 fps 的设备上火焰会比物理“慢” 2 倍，★★★ 的相位解会直接失效——而玩家会认为是自己操作问题。这是本关最容易踩、也最难查的实现错误。
