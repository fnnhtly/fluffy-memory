## 0. 已拍板的三个决定（用户确认）

| 决定 | 取值 | 理由 |
|---|---|---|
| 首版范围 | **1-1 ~ 1-5 垂直切片**（5 关） | 只需 6 个零件就能验证"建造即解谜 + 交互件即键位"，v1.0 自己也建议保垂直切片 |
| 屏幕方向 | **横屏 1280×720** | 千星奇域五个画布**全是横屏**（1280×720 / 1560×720 / 1280×960 / 1600×900 / 2100×900），v1.0 的"竖屏为主"在该平台无法成立 |
| 工程 | **新建 `workspace/roll-away-pig`**，从零写 | 与 `tumble-piggy`（同题材原型）解耦；tumble-piggy 作为技术来源，不继承其代码 |

## 1. 一句话概念

用有限的零件拼一辆注定会散架的载具，把猪送到终点；建造期玩家是全知的工程师，发射后只能按最多三个交互键看着它翻车。

**核心张力 = 建造期的确定性 × 运行期的不可控性。** 所有机制必须强化这个对立。

## 2. 四条设计支柱（与反支柱）

| 支柱 | 含义 | 我们不做的事 |
|---|---|---|
| 建造即解谜 | 难度在"怎么搭"，不在"怎么操作" | 不做需要精准操作的动作关 |
| 失控的观赏性 | 载具必须是活的：晃、散、翻 | 不做硬编码轨迹的伪物理 |
| 失败成本趋近于零 | 重开 ≤ 1 秒，失败信息可读 | 不做长流程、读条、惩罚 |
| 零件即语言 | 零件少而深，靠组合产生深度 | 不做几十种零件的收集堆砌 |

## 3. 切片范围（P0）

### 3.1 六件零件（v1.0 的 18 件里仅这 6 件进切片）

| 零件 | 类别 | 质量 | 功能 | 首次出现 |
|---|---|---|---|---|
| 木框 `wood_frame` | 结构 | 1.2 | **中空结构件**：四面可挂载，中间能塞下一个小猪；耐久 2 | 1-1 |
| 木轮 `wood_wheel` | 动力 | 0.6 | 高摩擦、低速、爬坡强；**冰面抓地 ×0.15** | 1-1 |
| 铁轮 `iron_wheel` | 动力 | 0.9 | 中摩擦、高速；**冰面抓地 ×0.8** | 1-4 |
| 马达 `motor` | 动力（被动持续） | 1.8 | 持续扭矩，耗能 4 / 秒 | 1-3 |
| 电池 `battery` | 动力 | 1.0 | 能量 +100 | 1-3 |
| 打气筒 `pump` | 动力（手动交互，**方向件**） | 0.8 | 按住蓄力、松开放出瞬时推力，**方向由组装期朝向决定**；上限 1 次/秒 | 1-2 |
| 小猪 `pig` | 内嵌件 | 1.5 | **只能放进中空木框**（同格内槽），是胜负判定对象；框碎了才裸露 | 1-1 |

> **与 v1.0 的差异**：v1.0 的"轮胎材质对抗"只给了设计意图（"木轮打滑 / 铁轮适合冰面"），
> 没说清到底是"抓地更强"还是"滚动更顺"。切片按**冰面抓地系数**实现（木轮 0.15 / 铁轮 0.8），
> 因为这样 1-4 的 ★★★「不撞墙」才成立：木轮在冰上打滑失控，铁轮可控。

### 3.2 核心机制清单（P0 必须全部成立）

1. **网格建造**：1 格 = 1 m = 32 逻辑像素；建造区 6 列 × 8 行（192×256 px）。
2. **放置与朝向**：拖拽放置、靠近吸附；零件挂在木框上，零件可旋转 4 向。
   **中空木框**：木框本身是一圈边框，中间是空的 —— 小猪要拖进**已有木框的那一格**（占该格内槽），
   放空地会被拒绝（`need_frame`）。内槽只放得下一件，且计入质量与重心。
3. **方向件（喷气/推进）**：带推进方向的零件（首批：打气筒；后续：风扇/螺旋桨/可乐瓶/火箭）
   在组装界面会用**金色箭头**画在格心，箭头就是它喷气的方向；切换方向有三种等价操作：
   右键点该格 / 按 `R`（光标所在格）/ **再点一次已放的同一零件**（`tryPlace` 返回 `rotated`）。
   也有显式按钮「↻ 换方向」。物理上冲量沿**零件朝向 × 车体当前旋转**施加，不是固定朝车头。
3. **质量与重心**：实时显示总重、重心偏移、总推力、预计爬坡角；倾覆判定用重心投影。
4. **交互件即键位**：每放一个手动交互件，运行期多一个按钮，**上限 3 个**。
5. **三类动力源**：被动持续（马达）/ 一次性脉冲（切片的打气筒算"手动蓄力"，P1 才加可乐瓶）/ 手动交互（打气筒）。
6. **能量预算**：电池 +100，马达 4/s；能量耗尽马达失效但车不消失。
7. **三星**：★通关 / ★★集齐木箱 / ★★★关卡专属挑战，且 **★★ 与 ★★★ 必须冲突**。
8. **失败与重开**：猪受伤 > 2 / 掉出下边界 / 卡死 5 s 无位移；0.4 倍速回放 3 s + 归因文字；一键重开保留上次建造。
9. **关卡选择**：建造界面顶部 5 个关卡页签（`LevelTab_1..5`），随时切关，不影响已得星级。
   这是实现期加的功能（v1.0 没有），理由有二：①5 关切片需要有"回老关用新零件刷三星"的中观循环；
   ②每个用例必须能单独进某一关，否则 1-5 的用例要先打穿 4 关（见 `tests/cases.md` 说明）。

## 5. 单项规则细节（写代码前必须定死）

### 5.1 伤害与失败

| 事件 | 判定 | 表现 |
|---|---|---|
| 落地冲击 | 接触速度 > 6 m/s 时，每件零件 −1 耐久；> 10 则 −2 | 屏幕轻震 + "咔" |
| 木框耐久 0 | 该木框碎裂，载具质量与重心即时重算 | 碎片特效（不参与物理） |
| 猪受伤 | 冲击 > 8 m/s 时猪 HP −1（HP 3） | 猪表情变化（切片用颜色/缩放代替） |
| 猪 HP ≤ 0 / 掉出下边界 | 立即失败 `pig_dead` / `out_of_bounds` | 0.4× 回放 3 s + 归因 |
| 卡死 | 连续 5 s 位移 < 0.2 m 且未通关 | 失败 `stuck` |
| 超时 | 单局运行 > 120 s | 失败 `timeout`（切片收紧 v1.0 的 180 s） |

归因文字（失败回放时显示，只给方向不给解法）：重心偏后 → "把重零件往后挪"；动力不足 → "也许需要更大的轮子"；结构断裂 → "试试在底盘加弹簧"。

### 5.2 三星结算

```
stars = 1                                  -- ★ 通关
if boxesCollected == boxesTotal then stars += 1   end   -- ★★
if challengePass(state) then stars += 1    end          -- ★★★，逐关定义
```
1-5 的 `challengePass = (motorUseCount == 0)`；1-2 是 `pumpPressCount == 0`；1-3 是 `energyLeft >= 30`；1-4 是 `wallHitCount == 0`；1-1 无 ★★★（最多 2 星）。

### 5.3 重开

一键重开 = 回到该关建造界面，**自动载入上次方案**（零件位置、朝向全保留），清空星级与运行状态。目标：从失败到再次发射 ≤ 1 秒。

## 7. 千星奇域落地约束（含实测依据）

| 约束 | 事实 | 应对 |
|---|---|---|
| 画布 | 官方 5 个预设全为横屏：1280×720、1560×720、1280×960、1600×900、2100×900 | 以 1280×720 为设计基准；PC 等比放大留边 |
| 坐标 | 原点左下、Y 向上；`SetAnchoredPosition` 无父层级时以画布左下为原点 | 设计坐标（左上原点）→ `anchoredPosition` 需换算（tumble-piggy 已验证公式） |
| 图元 | 只能显示 100001–100006 六种图元；图片没有 `raycastTarget` | 地形/UI 全靠"图元 + 染色 + 旋转"；交互按钮垫在图形下面 |
| 绘制预算 | 一张 40×14 地图有 560 格，逐格画不现实 | **地形按"列带合并 + 特殊格单画"**：可见约 40 列 → 40 条带 + 火口/熔岩/木箱约 15 个 + UI ≈ 120 图元 |
| 控件数量 | tumble-piggy 实测 ~320 个控件在模拟器 30fps 正常 | 切片控制在 ≤ 200 个；真机待验证 |
| 关卡数据 | 客户端脚本**无文件读写**，只有 `script:GetParam` 与自定义变量 | 关卡表内嵌 Lua（由 JSON 构建生成），保持同一 schema 便于迁回 |
| 回放 | 无原生回放/倒带 API | 自建 3 秒环形缓冲（车辆状态 ~10 个 float × 30 fps × 3 s = 900 float），失败后按 0.4× 播放 |
| 交互键 | 客户端按钮控件 + `CursorClick` 可用（tumble-piggy 已实测） | 右下角最多 3 个按钮，直接映射"交互件即键位" |
| 物理步进 | `OnUpdate(dt)` 帧率不稳（模拟器 30fps） | 固定 60 Hz 累加器 + 4 子步，火焰计时与物理共用同一个固定步（v1.0 §C.5 的坑） |

## 10. 实现期修正（步骤 3 校准后回写，均已生效）

这些是"照文档做但物理上不成立／做不出来"的地方，全部在 HTML 原型里被验证，改动以实测为准。

| # | v0.1 原样 | 改成 | 原因 |
|---|---|---|---|
| 1 | 1-1 / 1-2 是 30 m 平地 | **坡路开局**（起点就在 3 m 高的缓坡上） | 没有马达的车在平地上永远不会动；坡路也正好呼应 1-5 ★★★「重力即动力」 |
| 2 | 地形"1 格抬 1 米" | 高度场做 **3 次 5 点高斯平滑** + 单格台阶改 1:3 斜坡 | 不平滑时任何抬升都是 45° 斜面，需要 11.3 m/s²，比马达 6 还高，谁都上不去 |
| 3 | 1-4 ★★★「不撞墙」 | **「不翻车（倾角 ≤ 45°）」** | 高度场地形里没有独立"墙"；冰面打滑翻车才是真实风险 |
| 4 | 1-4 冰面平道 | **6 m 冰面助跑 + 1:2 冰坡** | 长助跑会让木轮靠惯性冲上去（10.7 m/s），关卡的"材质对抗"就失效了 |
| 5 | 1-5 3 m 深沟 | **3 m 宽、1 m 深的凹沟** | 3 m 深沟在无马达时爬不出来；1 m 时 ★ 能冲过、★★ 能下沟取箱再爬出 |
| 6 | 马达完全依赖电池 | **马达自带 12 电量**（电池 +100） | 文档 §6.1 的 1-5 只给马达不给电池，否则"用马达"这条路永远不成立 |
| 7 | 1-2 打气筒 ×1 | **×4**（第 4 个被"交互键上限 3"挡下） | 让上限在首章就能被玩家看见、也能被用例覆盖 |
| 8 | 1-1 无 ★★★ | 保持（最多 2 星） | `stars = 1 + 木箱 + 挑战`，没有挑战就只有 2 星 |
| 9 | 小猪是自动挂在车上的角色 | **小猪变成可放置的内嵌件**（用户要求：结构中空、角色放进去） | 视觉与玩法都更像参考；带来两条新规则：放空地拒绝（need_frame）、框碎了猪才裸露 |

### 仍然成立的契约

- 6 个零件、6×8 建造区、1 格 = 1 m = 32 px、交互键上限 3、三类动力源、能量预算、
  三星公式、失败四态、一秒重开、关卡 JSON schema —— 都没变。
- ★★ 与 ★★★ 的冲突性：1-5 在实测里**可以一次拿全**（沟只有 1 m），
  这条弱点已知，留给 2-5《悬崖快递》（气球/伞）去体现。

## 11. 第三轮反馈修正（用户试玩后，2026-04-19）

用户在真浏览器里试玩后指出的问题与处理（全部已实现并验证）：

| # | 用户反馈 | 处理 |
|---|---|---|
| 1 | 底部零件槽挡视野 | 槽位 56→46px、去掉底栏、只留槽；悬停/选中的槽**上方显示零件名** |
| 2 | 存在吃不到木箱的情况 | 判定从"车心距离"改成**包围盒距离 1.7 m**（轮子/挂件碰到就算） |
| 3 | 车建好从空中掉下来，木结构直接摔没 | 出生高度改成**刚好贴地**（+0.01），并加 **0.6 秒出生保护期**不计算结构伤害 |
| 4 | 木结构没了角色不会掉下来 | 框碎 → 内嵌件变成**自由落体**（重力 + 落地弹跳 + 滚动），停住 0.5 秒即判 `pig_lost` |
| 5 | 喷气方向看不懂 | 箭头改成"深色打底 + 白包边 + 本体色 + 实心三角"，长度伸出格子外，尾部画喷气短线；悬停额外显示「上/下/左/右」 |
| 6 | 希望同色同类零件一起启动 | **颜色组**：同种零件 = 同一个组；行驶时底部按钮按组显示（颜色 = 零件色 ＋ 名字 ＋ ×数量），按一下该组**所有**零件同时响应 |
| 7 | 已放的零件不能拖动移动 / 直接拖会从仓库新建一个 | 单击 vs 拖拽分流：按下先挂起，**移动超过 8px 才拿起**，松手落子；无效位置自动放回原处 |
| 8 | 第二关根本玩不了 | 真因是渲染里 `ca` 未初始化抛异常，**第一帧就把 rAF 循环打死**（已修）；现在 1-2 通关 2 星 |
| 9 | 选结构时看不到名字 | 槽位上方工具提示 + 拖拽时跟随光标显示名字 |
| 10 | 格子里不止能放角色，还能放别的 | 内嵌件机制通用化：**小猪、电池**都只能放进中空木框（`inner: true`） |
| 11 | 结构应有阶段性损坏，而不是直接消失 | 木框耐久 **3 段**：完好 → 裂纹 → 破损（发黑 + 缺口）→ 碎掉；伤害带 0.35s 冷却 |

### 由此确定的规则（进 Lua 时照这个做）

- 木框耐久 3，单次 6 m/s 以上冲击扣 1（14 m/s 以上扣 2），0.35s 冷却；
- 内嵌件：`pig` / `battery`，必须放进已有木框的格子，占内槽，计入质量与能量；
- 颜色组：`PARTS[part].color` 即组色；一组一个按钮，组内零件各自按自己的朝向响应；
- 掉出来的内嵌件是自由体（圆体 + 重力 + 地面滚动），停住即 `pig_lost`。
